# Audit Checklist Agent

Use this skill's audit checklist as an attack map, not a mechanical tick-box substitute for exploitation. Check every pass below. For each applicable high-impact item, produce a concrete exploit/test trace or a reason it is blocked. Feed exploitable results into the standard FINDING/LEAD output; do not emit a separate checklist report.

## Checklist passes

0. **Scope and artifacts:** identify Tolk/FunC/Tact and compiler/TVM assumptions; build commands, flags, stdlib, ABI, source maps, wrappers, generated output, external contracts/code cells/services, roles, and tool limitations. Review language changelogs for used features and ensure generated artifacts are rebuilt.
1. **Architecture and threat model:** build internal/external/bounce/deploy/upgrade message and value-flow graphs; map handler auth, parsing, state, sends, gas, bounce, and action failure; define invariants and attack partial/interleaved execution, stale checks, synchronous-call assumptions, downstream failure, and silently trusted infrastructure.
2. **Entry points:** inventory internal/external/bounce/empty/fallback/get/deploy/upgrade/plugin paths; verify caller policy and pre-state-change checks; attack silent unknown opcodes, junk-message griefing, ordinary parsing of bounces, incomplete Tolk unions, Tact fallback gaps, and unsafe getter consumers.
3. **Authorization and replay:** verify every state-changing caller policy, admin blast radius, hidden privileged paths, derived Jetton/NFT identities, forwarded identity fields, workchain, full signed intent, seqno/nonce under action failure, cross-contract/wallet/workchain replay, front-running, and null/default privileged identities.
4. **External messages:** attack accept-before-validation, expensive pre-accept work, unbounded post-accept work, bad wallet validation order, unsafe Tolk commit placement, randomness, repeated messages, old seqno, expired time, wrong subwallet, and wrong recipient.
5. **Asynchrony:** test delay, lost action, bounce, duplicate, retry, timeout, cancellation, and parallel flows; carry-value discipline; reversible pre-send state; `+2` partial execution; pending recovery; idempotency; scoped query IDs combined with sender/op/state/amount; shared-state races; and success/bounce/retry/late interleavings.
6. **Bounce:** map every bounceable send to recovery; restore balances/supply/locks/pending/debt/LP/claims; test Jetton flows, truncated bodies, Tact limits, all Tolk `BounceMode` values, rich schema compatibility, mixed modes, and authentication of reachable sender/query/op/state/amount. Establish protocol-generated bounce provenance before claiming a missing check permits forgery.
7. **Sends and action phase:** inventory sends and reserves with destination/value/mode/bounce/body/StateInit/order/failure; reject magic modes; check 64/128/+1/+2/+16/+32 combinations, external-message modes, `+2` versus `+16`, non-ignored errors, remaining-value semantics, authorized destruction, action limits, bounded batches, failed-action recovery, and off-chain logs used as truth.
8. **Gas, fees, and storage:** measure worst cases; account for compute/forward/action/storage/deploy/excess/refund/service fees; test reserve modes and ordering, freeze/delete debt, unbounded storage and attacker griefing, bounded loops/traversal/sends, correct excess destination and races, and fee recalibration.
9. **Storage and cells:** verify documented compatible schemas and migrations; FunC load/store order; Tolk/Tact serialization boundaries; 1023-bit/4-ref/depth limits; full slice consumption; raw tags/bits/refs; assert-end behavior; type symmetry; checked success flags; namespace/shadowing; and protected schema/code cells.
10. **Arithmetic and types:** check signedness, positive/balance/max bounds, negative spoofing, multiplication/division order, rounding owner, fee/slippage zero/dust/width limits, Tolk sized writes, Tact casts, unsafe casts, and reserved error codes.
11. **Randomness and time:** reject high-value randomness without commit-reveal, randomness in external receivers, validator-influenced outcomes, incorrect initialization, clock/deadline edges, locked expiration flows, and commit-reveal lacking domain/deadline/replay/refund safety.
12. **Upgrades and governance:** gate code/data replacement; review Tact implicit save; validate new code and migrations; preserve layout/code/ABI/wrapper/indexer assumptions; model update timing; protect withdrawals during governance/pause; block hidden upgrade paths; validate plugins/third-party code; and document key-compromise recovery.
13. **Tolk:** check changelog/artifacts, assembler/raw cells, rebuilt generated output, modern entrypoints, complete unions, lazy validation, assert-end, address/null/casts/raw types/typed cells, sized writes, `createMessage`, `.toCell()`, `UnsafeBodyNoRef`, `sendRawMessage`, AutoDeployAddress/StateInit, every `BounceMode`, commit placement, and globals-as-state.
14. **FunC:** check `impure`, modifying methods, storage order, `end_parse`, shadowing, accept order, send modes, code/data timing and migration, third-party code plus COMMIT/OOG, and malformed raw-cell tests.
15. **Tact:** check current compiler/wrappers, receiver and bounce coverage, bounce payload limits, trait auth, optionals, native/asm, dangerous `setData`, stale `myBalance`, exit codes, and security-versus-gas tradeoffs.
16. **Protocol families:** verify Jetton wallet/notification identity, bounce supply/balance recovery, forward payload and TEP-74; NFT owner/item derivation/index/metadata/randomness; DEX/vault/lending/bridge false deposits, slippage/deadline/fees, LP symmetry, oracle assumptions, bridge domain, parallel claims/races, and refund bypasses.
17. **Testing and tools:** look for unit/integration coverage of every path; failure/bounce/funds/destination/size/cell/sender/workchain cases; race/replay/gas/migration/fuzz/mutation tests including lazy and modes; consider Misti, TON Symbolic Analyzer, tolk-less, Universalmutator, and linters without treating output as proof; classify evidence source.
18. **Red flags:** immediately trace accept-before-auth, carry-all/destruction, missing bounce, irreversible pre-send state, silent opcode, missing identity policy, payload identity, fake Jetton/NFT sender, ungated code/data, raw messages/cells, unsafe casts/null/raw types, unbounded work/storage, weak randomness, suppressed action failure, disabled assert-end, hidden privileged paths, and stale generated output.
19. **Evidence:** derive message/value graphs, storage migrations, role powers, send/reserve and entry-point tables, per-handler gas, test gaps, exploit/not-applicable rationale, accepted risks, and code/test/tool/manual evidence classification when needed to prove or reject a finding.
20. **Precision:** model `+2` non-ignored cases; treat `+16` as relevant only outside `+2` suppression; distinguish all action-failure outcomes; never use query ID alone as authorization; allow permissionless mutation only with explicit identity policy; treat Tact `setData` with implicit save; review reserve actions like sends.
